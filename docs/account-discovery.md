# 获取自己的 IPTV 身份

大多数用户不知道 IPTV 账号，这是正常的。机顶盒通常已经保存业务身份并自动认证；`UserID` 可能与宽带账号不同。可以先查看自己机顶盒的网络/业务信息页面，或联系运营商查询。机身贴纸上的 MAC 有参考价值，但 **物理 S/N 不一定是登录请求中的协议 SN**。

如果无法从合法管理页面取得，可在自己的机顶盒开机认证时做一次有限抓包。只抓自己的 IPTV 链路，不抓全家日常流量，不尝试突破加密或盗用别人身份。不同固件如果改用 TLS 或不同认证协议，下述方法可能不适用。

## 准备观察点

- 优先在机顶盒经过的 Linux IPTV 桥上观察，或将交换机的机顶盒端口镜像到抓包口。
- 普通交换机没有镜像能力；同网段电脑通常看不到另一设备的单播认证。
- 机顶盒不必直插光猫，只要已经正确接入运营商 IPTV 网络。
- 先确认机顶盒业务可用，记录原接线，不为抓包随意改光猫/VLAN。

## 有界抓取

下面是 Linux 示例，替换接口与 MAC 后使用。目录应仅管理员可读。`timeout` 是 GNU 工具；若路由器没有它，手工停止并同时设置包数上限。不要无人值守长期抓取。

```bash
umask 077
mkdir -p /root/iptv-private
timeout 90 tcpdump -i YOUR_IPTV_INTERFACE -s 0 -c 10000 \
  -w /root/iptv-private/bootstrap.pcap 'ether host 02:00:00:00:00:01'
```

开始抓取后，让自己的机顶盒正常重新上电并等到首页出现，再停止抓取。不需要循环重启。示例 MAC 是虚构地址，必须换成自己的。

把文件通过安全渠道传到本地，在 Wireshark 中查看 HTTP 请求、表单与 TCP 重组内容。常见线索包括 `4kLogAuth.do`、`UserID`、`SN`、`ottauth`。字段应来自同一次自己的认证链，不能将不同账号或旧会话混用。

记录到本地 `config.json`：

| 字段 | 从哪里确认 |
| --- | --- |
| `user_id` | 登录请求中的 `UserID` |
| `protocol_sn` | 同一请求中的 `SN` |
| `mac` | 自己机顶盒身份，结合贴纸、DHCP 和认证参数核对 |
| `auth_host` | 初始认证请求的主机与端口 |
| `interface` | 部署主机实际连接 IPTV 的 Linux 接口名 |

不要把 `UserToken`、`JSESSIONID`、BIMS token 或抓到的 authenticator 当作长期配置。这些是会话数据；HomeCast 使用自己的身份重新获取挑战、生成当次 authenticator，并根据网卡当前 IPv4 发起认证，所以日常更新不需要再次抓包，也不要求固定运营商分配的 IP。

## 验证与清理

1. 运行 HomeCast，手动刷新并确认频道及节目单都成功更新。
2. 用自己的客户端验证一条已订阅频道。接口返回频道不等于所有频道都有播放权限。
3. 确认下次刷新能重新认证，再删除路由器和本地不再需要的原始 PCAP 与临时文件；确需保留时应加密并限制访问。
4. 不要把 PCAP、真实配置、认证截图或运营商响应提交到 issue / PR。

失败时先检查 IPTV 接口 IP、VLAN 链路、自己的账号字段和系统时间。不要把重复抓包作为每日刷新方式。更换机顶盒、业务账号或运营商协议变化时，才可能需要重新确认身份或修改适配器。
